# kernel

`kernel` builds the RISC-V boot image used by Buckyball. Sources are under `bb-tests/workloads/lib/kernel`. Outputs go to `bb-tests/output/kernel`, or to `bb-tests/output/kernel/<chip>` when `--chip` is set.

## Image contents

The image contains OpenSBI, a Linux Image, and a rootfs. OpenSBI performs machine-mode initialization, Linux runs user programs, and the rootfs contains BusyBox, `/init`, and workload or model files. Simulation and FPGA flows use the same `fw_payload` artifacts.

```text
0x00010000  BootROM
0x80000000  OpenSBI + Linux Image + initramfs/rootfs
```

## build

```bash
bbdev kernel --build
bbdev kernel --build '--chip toy'
bbdev kernel --build '--chip pebble --model lenet'
bbdev kernel --build '--chip pebble --model lenet --model-storage ddr --guest-memory-mib 4096'
bbdev kernel --build '--chip toy --interactive'
```

The flow in `bbdev/api/steps/kernel/01_build_event.step.py` configures `bb-tests/workloads/lib/kernel` with CMake, builds the `kernel-build` target, then converts the binary to Verilog hex. With a chip and no model, the workload list comes from `examples/chips/<chip>/kernel/workloads.toml`.

Default outputs are:

```text
bb-tests/output/kernel/fw_payload.bin
bb-tests/output/kernel/fw_payload.elf
bb-tests/output/kernel/fw_payload.hex
```

Chip, model, memory, and storage options add suffixes to the filename, such as `fw_payload-pebble-linux.bin`, `fw_payload-lenet.bin`, or `fw_payload-lenet-mem4096M-ddr.bin`.

## Parameters

- `--chip`: select a chip configuration. The chip must exist and its configuration must be installed.
- `--model`: place a ModelTest in the rootfs; requires `--chip`. Build the model workload first with `bbdev workload --build '--chip <chip> --model <model>'`.
- `--interactive`: keep an interactive `/init` and enter a shell instead of running workloads automatically.
- `--hart-count`: set the number of visible harts. With `--chip`, it must match the generated topology; without a chip, the default is 64.
- `--guest-memory-mib`: set guest memory from 1 to 16384 MiB; the default is 512 MiB.
- `--model-storage`: choose `initramfs` or `ddr`. `ddr` requires a model and guest memory below 16384 MiB; it also produces a `.load.json` manifest.

All chip and model artifacts are generated by the tool. Rebuild after changing configuration, workloads, or model inputs.
